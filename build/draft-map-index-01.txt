               MAP: Family Index and Submission Overview
                           draft-map-index-01

Abstract

   The Manolito Agent Protocol (MAP) is a family of specifications for a
   decentralized, permissionless network of autonomous AI agents.  MAP
   evolves the capability-oriented spirit of the historical Manolito
   (MP2P) file-sharing network into a modern agent fabric in which
   participants advertise _what they can do_ — models, tools, memory
   domains, compute — and requesters route work by semantic capability,
   verifiable evidence of past behavior, price, and locally measured
   performance.  This document is the *cover/index* for the MAP family:
   it lists the companion documents, states the reading order, and
   records the submission status.  Each companion document carries its
   own normative text; this index defines no wire format, code point, or
   protocol behavior.

1.  Family overview

   MAP is written as a set of focused Internet-Drafts rather than one
   monolith, so each concern (identity, transport, discovery, tasks,
   trust, payments, operations) can advance and be reviewed
   independently while sharing one envelope, one identity model, and one
   registry index.  The shared technical foundations are:

   *  a self-certifying Ed25519 identity (AgentID ≡ did:key ≡ libp2p
      PeerID);

   *  a deterministic CBOR + COSE_Sign1 signed envelope with downgrade-
      resistant

   negotiation and channel binding;

   *  a family-wide registry index (draft-map-wire-01) that is the
      single

   source of truth for every assigned code point;

   *  evidence-based local trust (dual-signed ExecutionReceipts) rather
      than

   self-asserted reputation.

   The motivation, problem statement, and design critique are in draft-
   map-intro-01 and 01-design-critique.md; the architecture, trust
   model, and threat catalog are in draft-map-arch-01.

4.  Submission status

   The family was written for the IETF Independent Stream (each draft's
   submissiontype: independent front-matter records this).  That stream
   cannot create the ~20 IANA registries this family defines, nor grant
   the registration policies they use (RFC 8726 §2/§4/§5), so the
   family's registries are stewarded outside the RFC series per draft-
   map-ops-01 §3.5 and only narrow, registry-free extracts are
   submitted.  SUBMISSION.md records the current plan.

   Both reference implementations (map-rs, map-go) pass the full test-
   vector set and the live pairwise interop matrix (26/26 — 16 core, 6
   task, 4 pay), which meets draft-map-ops-01 §6.1 mechanically; both
   are the work of one author, so the independence criterion is not met
   substantively.  The documents remain in draft pending human/expert
   review.

5.  Security Considerations

   This document is a family index and defines no protocol mechanisms of
   its own; it therefore introduces no new security considerations.
   MAP's security model is normative in the protocol documents: draft-
   map-core-01 (envelope integrity, session channel binding, anti-
   replay), draft-map-identity-01 (agent identity and delegation
   attenuation), draft-map-trust-01 (receipt-based, self-reported-trust-
   free reputation), and draft-map-pay-01 (settlement evidence and
   disputes). draft-map-arch-01 states the family threat model.
